# CAUSA Frontend (Phase 1)

This is the standalone React frontend for **CAUSA**, an architecture-aware failure diagnosis system for microservices. It is built as a modernized version of `orca-ui`, with OpenRCA-specific branding and backend proxy layers stripped out, and a self-contained, zero-dependency client-side mock data layer implemented.

> **Update (deployment):** the frontend now also runs against the deployed [Causa-backend](https://github.com/Pranjall-Gupta/Causa-backend) (Heroku + Postgres) and is hosted on Vercel. The mock data layer is still available and is now opt-in (see [Environment Variables](#environment-variables)).

**Live demo:** [<VERCEL_URL>](https://causa-frontend-two.vercel.app/)
(The public demo shows simulated telemetry generated by the backend's demo mode.)

## Project Repositories

CAUSA is split across four repos. This one (frontend) is the entry point — start here.

| Repo | What it is |
|---|---|
| **Causa** (this repo) | React frontend — dashboards, topology graph, RCA views |
| [Causa-backend](https://github.com/Pranjall-Gupta/Causa-backend) | Spring Boot backend — OTLP ingestion, dynamic topology, anomaly detection, heuristic RCA scoring |
| [Causa-test-services](https://github.com/Pranjall-Gupta/Causa-test-services) | Sample microservices used to generate real trace/log/metric data for testing |
| [Causa-plugin-java](https://github.com/soham-kolhe/Causa-plugin-java) | Java plugin developers add to their own services to emit data to CAUSA |

## Codebase Map

### Folder Structure
- `/public` - Contains the HTML shell (`index.html`) and favicon.
- `/src` - The core application source files.
  - `/assets` - CSS and SCSS stylesheets defining tables, fonts, variables, and layouts.
  - `/components` - Individual React components making up the interface.
  - `mockData.js` - Contains mock datasets representing 4 microservices, dynamic alerts, and ranked Root Cause Analysis trajectories.
  - `mock.js` - Global Axios request interceptor that routes `/v1/*` requests to the mock dataset.
  - `index.js` - Frontend entry point, rendering the routing layout shell and loading the mock layer.

### Component Map
1. **Layout Shell**:
   - [Navbar.js](src/components/Navbar.js) - Rendered at the top of the interface. Displays the application brand (**CAUSA**) and a live badge counting the current active critical/warning incidents.
2. **List & Incident Views**:
   - [Alerts.js](src/components/Alerts.js) - Renders the `/alerts` view which lists all active microservice alerts in a paginated, filterable table. Includes severity sorting (Critical > Warning > Info) and direct links to analyze the root causes.
   - [AiFixSuggestion.js](src/components/AiFixSuggestion.js) - Requests an LLM-generated fix suggestion (`POST /v1/fix-suggestion`) for an alert and renders the summary, numbered remediation steps, and confidence. The project API key is read from the browser's `localStorage` (`causa_api_key`).
   - [Onboard.js](src/components/Onboard.js) - Operator page that creates a project (`POST /v1/admin/projects`). It asks for a project name and the backend's admin key, and returns the project API key.
3. **Topology Visualizations**:
   - [Graph.js](src/components/Graph.js) - Renders the `/graph` view. It draws an interactive node-link graph of the microservices topology using **D3.js**, complete with zoom/drag controls, namespaces filtering, and status attributes.
   - [GraphUtils.js](src/components/GraphUtils.js) - Implements algorithms like namespace filtering, node-kind visibility, and `detectFaultTrajectory` which automatically identifies active fault propagation paths.
   - [NodeDetailCard.js](src/components/NodeDetailCard.js) - Displayed as a floating sidebar when clicking a node in the topology graph. Displays raw metadata properties via `react-json-view` and includes the **Analyze** button for alert nodes.
4. **Timeline & RCA Visualizations**:
   - [RCA.js](src/components/RCA.js) - Renders the `/rca` view, showing the sub-graph representing the specific root cause trajectory.
   - [Selector.js](src/components/Selector.js) - The sidebar rendering the list of ranked paths.
   - [Item.js](src/components/Item.js) - Formats each individual ranked trajectory in the list with its probability score (Weak, Medium, Strong) and source-to-root-cause endpoints.

## Standalone Running Instructions

To start the application locally, run these commands inside the `causa-frontend` directory:

```bash
# 1. Navigate to the project directory
cd causa-frontend

# 2. Run the development server
npm start
```

- **Port**: The application runs on **port 3000** (http://localhost:3000) by default.
- **Node Version**: Optimized for **Node.js v22.2.0** and **npm 10.9.3**.
- **OpenSSL Compatibility**: Configured to run with `set NODE_OPTIONS=--openssl-legacy-provider` in `package.json` to handle old Webpack legacy cryptography compatibility on newer Node engines.

### Environment Variables

| Variable | Purpose |
|---|---|
| `REACT_APP_BACKEND_HOST` | Backend base URL, for example `https://your-backend.example.com` (or `http://localhost:5000` locally). **No trailing slash and no `/v1`**: the code appends `/v1/...` itself, and a trailing slash produces `//v1/...` URLs that the backend answers with 404. |
| `REACT_APP_USE_MOCK` | Set to `true` to use the built-in mock data layer instead of a backend. Leave unset to use the real backend. |

> **Security:** every `REACT_APP_*` value is baked into the public JavaScript bundle at build time. Never put an API key or the admin key in an env var. The project API key is read from the browser's `localStorage` (`causa_api_key`), and the admin key is typed by the operator on the Onboard page.

Env vars are applied at **build time**: after changing one on your host, redeploy.

## Mock Data Layer Design

The frontend intercepts all network calls transparently using `axios.interceptors.request` configured in `src/mock.js`. Instead of sending HTTP requests to the backend host (configured as `http://localhost:5000` in `.env`), the interceptor overrides Axios's network adapter and responds instantly with:
1. **4 Mock Services**: `checkout-api`, `order-service`, `payment-service`, and `inventory-service` (represented as Kubernetes services, pods, and nodes).
2. **Dynamic Timestamps**: Alerts and topology timestamps are dynamically calculated relative to the system's local time (`Date.now()`), so incidents look fresh.
3. **Automatic Fault Highlighting**: Due to the built-in `detectFaultTrajectory` algorithm, if a downstream node (like `payment-service`) and upstream node (like `checkout-api`) both have active alerts, the communication path between them is highlighted in red.
4. **Ranked Trajectories**: Click **Analyze** on `CheckoutApiHighErrorRate` to see three distinct root cause paths scored by likelihood (95% Payment timeout, 65% Inventory database latency, 35% checkout-api local pod resources).

> **Update:** the mock layer is now opt-in. `src/index.js` only loads it when `REACT_APP_USE_MOCK === 'true'`; otherwise requests go to the backend at `REACT_APP_BACKEND_HOST`.

## Using the App

**Operator (the person who runs the deployment):**
1. Open the **Onboard** page. Enter a project name and the backend's admin key (the `CAUSA_ADMIN_KEY` configured on the backend).
2. The backend returns a project API key (`causa_proj_...`).
3. Configure your telemetry sender (the [Causa-plugin-java](https://github.com/soham-kolhe/Causa-plugin-java) plugin, or the mock script in Causa-backend) to send that key in the `X-Causa-Api-Key` header.

**Anyone viewing the dashboard:**
- **Graph**: interactive topology of services, pods, and alerts.
- **Alerts**: sortable list of active alerts, with an **Analyze** action.
- **RCA**: ranked root-cause paths for the selected alert.
- **AI fix suggestion**: LLM-generated summary and numbered remediation steps for an alert.

The dashboard only reads recent telemetry (see Known Limitations), so it is empty when no telemetry has arrived lately. The hosted demo avoids that by running the backend in demo mode, which generates simulated traffic.

## Backend API Specification (Java/Spring Boot)

`Causa-backend` implements the following three endpoints, consumed by this frontend:

### 1. Retrieve Incidents
- **Endpoint**: `GET /v1/alerts`
- **Response Shape**: `Array<Alert>`
```typescript
Array<{
  id: string; // Unique identifier (e.g. "alert-payment-timeout")
  origin: string; // Source monitoring system (e.g. "prometheus", "falco")
  name: string; // Standard alert rule name
  message: string; // Detailed description of the failure event
  severity: "critical" | "warning" | "info" | "Notice"; // Severity label
  source: {
    origin: string | null;
    kind: string | null;
    properties: {
      name: string | null; // Associated component name
      namespace: string;   // K8s namespace or "n/a"
    }
  };
  created_at: number; // Unix timestamp in seconds (seconds since epoch)
  updated_at: number; // Unix timestamp in seconds
}>
```

### 2. Retrieve Architecture Topology
- **Endpoint**: `GET /v1/graph?time_point={timestamp}`
- **Parameters**: `time_point` (optional Unix epoch timestamp in seconds)
- **Response Shape**: `GraphTopology`
```typescript
{
  nodes: Array<{
    id: string; // Unique element ID
    origin: string; // e.g. "kubernetes"
    kind: "cluster" | "node" | "pod" | "service" | "alert" | "deployment" | "config_map" | "secret";
    properties: {
      name: string; // Element name
      namespace: string; // K8s namespace (use "{}" for global resources like node/cluster)
      [key: string]: any; // Any metadata properties rendered in the detail card JSON viewer
    }
  }>;
  links: Array<{
    id: string; // Unique link identifier
    source: string; // Node ID of link origin
    target: string; // Node ID of link destination
    properties: {
      strength?: number; // Integer/Float to render weight/strength on the link
      [key: string]: any;
    }
  }>;
}
```

### 3. Retrieve Root Cause Analysis Trajectories
- **Endpoint**: `GET /v1/rca?source={alert_id}&time_point={timestamp}`
- **Parameters**:
  - `source`: The ID of the alert to analyze (e.g. `alert-checkout-high-error-rate`)
  - `time_point`: The Unix timestamp of when the analysis is requested
- **Response Shape**: `Array<Trajectory>` (Ranked list of paths)
```typescript
Array<{
  score: number; // Probability/strength score (0.0 to 1.0)
  nodes: Array<{
    id: string;
    origin: string;
    kind: string;
    properties: {
      name: string;
      [key: string]: any;
    }
  }>; // Ordered path from manifestation alert [0] to root cause node [length-1]
  links: Array<{
    id: string;
    source: string;
    target: string;
    properties: {
      strength?: number;
      [key: string]: any;
    }
  }>; // Graph links connecting the nodes in the path
}>
```

> **Note:** the backend accepts `time_point` on `/v1/graph` and `/v1/rca` but currently ignores it: results always reflect the present.

The frontend also calls two more endpoints:

### 4. Generate an AI Fix Suggestion
- **Endpoint**: `POST /v1/fix-suggestion` (header `X-Causa-Api-Key`)
- **Request body** (`symptomAlertId` is required, the rest optional):
```typescript
{
  symptomAlertId: string;
  trajectoryScore?: number;
  trajectory?: { nodes: object[]; links: object[] };
}
```
- **Response**:
```typescript
{
  alertId: string;
  provider: string;     // "AzureFoundry", or "Fallback" when the LLM was unavailable
  summary: string;
  suggestedFix: string; // numbered steps separated by newlines
  confidence: "HIGH" | "MEDIUM" | "LOW";
}
```

### 5. Create a Project (operator)
- **Endpoint**: `POST /v1/admin/projects` (header `X-Causa-Admin-Key`)
- **Request body**: `{ "name": string }`
- **Response**: `{ id: number, name: string, apiKey: string }`

## Deployment (Vercel)

1. Import this repo as a Vercel project (Create React App preset).
2. Set `REACT_APP_BACKEND_HOST` for the Production and Preview environments (value format above), then redeploy.
3. `vercel.json` adds a rewrite to `index.html` so client-side routes survive a page refresh:
   ```json
   { "rewrites": [{ "source": "/(.*)", "destination": "/index.html" }] }
   ```
4. If your host treats ESLint warnings as build errors (Create React App does when `CI=true`), set `CI=false` for the build.

## Known Limitations

- **Single-tenant dashboard:** graph, alerts, and RCA are not filtered per project, so data from different projects is mixed.
- **Public read endpoints:** `/v1/graph`, `/v1/alerts`, and `/v1/rca` need no authentication.
- **Short data window:** topology and alerts are computed from recent telemetry only, so the dashboard empties out when nothing has been sent recently.
- **Partly synthesized topology:** cluster/node layers, pod status, and pod IPs are generated by the backend, not read from a real Kubernetes cluster.
- **Simulated data in the public demo:** the hosted demo runs the backend's demo mode, so what you see is simulated telemetry, not data from real services.
- **LLM output is not verified:** fix suggestions can be generic or wrong. Treat them as a starting point, not a diagnosis.
